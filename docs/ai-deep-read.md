# AI 深读：从通知提取到执行建议

版本0.2.0在原有三个业务模块中扩展了“通知解析”环节：AI先提取可核对的行动，再独立生成一份可追溯的办理建议。未增加校园知识库、OCR、账号或云同步。

真实AI解析成功后，核对页自动请求 `/api/v1/deep-read`。它展示：

1. 一句话概括及其原文摘句。
2. 1—5项有顺序的执行建议，每项附理由和原文摘句。建议不是原文新增要求。
3. 最多3个原文未说明、办理前值得追问的问题。

例如，对于“导师不在校，请先邮件联系秘书申请电子签”的虚构通知，真实 `deepseek-flash` 调用把准备申请表和签字版计划书、导师不在校时申请电子签、截止前上传、公布日查询结果排列为条件化步骤，并提出学院系统入口和电子签邮件材料等问题。模型输出保存在忽略目录 `.local/evaluation/deep-read-complex.json`，没有真实师生资料或密钥。另一条提交项目书PDF的虚构通知也完成真实调用，见 `.local/evaluation/deep-read-live.json`。这两次成功仅证明特定样例的功能，不代表整体准确率。

后端按严格JSON结构解析，拒绝额外字段；概括和每条步骤都必须引用通知中的连续原文。校验只容忍空白和标点差异，并把通过的引用还原为原文片段；文字及大小写必须一致。格式或引用不合格时最多自动重试两次，仍不合格则显示错误，不伪造建议。与原解析共用令牌鉴权、分钟限流、每日额度、并发上限与超时预算。深读成功后随原通知保存在本机，可在待办的“来源”中回看，备份不包含连接令牌。失败时仍能核对和保存原候选事项。

模型可以提出通用的办理建议，但不能替用户确认学校规定、推断缺失时间、完成提交或保证办事结果。展示页明确区分“AI建议”和“原文要求”。
